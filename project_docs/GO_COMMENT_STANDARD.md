# **🔒【總則 — 全域硬性政策（Global Hard Policy）】**

以下條款為不可協商硬性要求，所有輸出皆必須符合：

1. **所有模板（A~H）為不可變動模板：**
    - 不得更改、刪除或新增欄位。
    - 不得調整縮排、空白、換行、符號。
    - **即使某欄位無內容或不適用，也必須完整保留該欄位。**
2. **每一種程式碼元素必須使用對應模板：**

| **元素種類** | **必須使用的模板** |
| --- | --- |
| File | A |
| Function | B |
| struct/type | C |
| interface | D |
| enum | E |
| 全域變數 | F |
| import 區塊 | G |
| inline comments | H |
1. **語氣規範（Language Style Requirements）：**
    - 必須使用「技術專業」語氣。
    - 必須保持「中性」、「嚴謹」、「客觀」。
    - 嚴禁使用口語化、比喻、對話式、主觀化語句。
    - 不得使用任何第二人稱或第一人稱（例如「你」「我們」「我」）。
    - 嚴禁填入情緒性、建議性、推測性語言。
    - 嚴禁使用範例除非模板要求。
2. **註解內容要求：**
    - 必須描述「設計意圖」、「邏輯理由」、「使用契約」、「限制」。
    - 必須避免描述語法表層行為。
    - inline comment 必須描述「intent」，禁止流水帳式重述。
3. **三組 import 區塊為強制要求（不可省略）：**

    即使沒有任何 import，也必須完整保留三組區塊及註解。

```

//
// 職責 (Responsibility):
//     [說明此檔案的核心責任與功能邊界。]
//     [描述此檔案在分層架構中的位置與角色。]
//
// 注意事項 (Notes):
//     - [列出使用此檔案時需要遵守的重要限制或契約。]
//     - [描述與併發、I/O、資源管理或外部系統的關係與假設。]
//     - [列出不可違反的層級依賴規範（如禁止依賴上層模組）。]
```

## **🧩 B. Function Template（函式註解模板）**

```
// [FunctionName] 函式用途一句話描述（動詞開頭）。
//
// 功能:
//   - [描述此函式的主要責任。]
//   - [描述核心邏輯的意圖與設計目的。]
//
// 參數:
//   - [param1]: [描述參數的語意、資料來源、可接受範圍或限制。]
//   - [param2]: [同上。若無參數，此欄位仍需保留並填寫「無」。]
//
// 回傳:
//   - [result]: [描述回傳值的語意與狀態。若無回傳，此欄位仍必須存在並填「無」。]
//   - [err]: [描述所有可能的錯誤狀態與語意，若無錯誤則填「無」。]
//
// 備註:
//   - [描述併發行為、不變條件、生命週期管理、資源釋放等。]
//   - [描述任何呼叫順序要求或可預期的副作用。]
func [FunctionName]([param1] [Type1], [param2] [Type2]) ([result] [Type3], [err] error) {
    // [說明此區段的意圖，例如前置驗證或狀態準備的技術理由。]

    // [說明主要邏輯區段的意圖，以系統層級觀點描述，而非語法表述。]

    // [說明收尾階段，例如統一錯誤路徑或釋放資源的原因。]
}
```

## **🧩 C. Struct / Type Template（結構體註解模板）**

```
// [TypeName] 結構用途一句話說明（名詞開頭）。
//
// 功能:
//   - [描述此結構在系統中的角色與用途。]
//   - [若此結構對應至外部格式（例如 YAML/JSON），需明確說明對應關係。]
//
// 欄位說明:
//   - [FieldA] (yaml:"[field_a]"): [描述欄位語意、使用場景、是否必填、預設行為。]
//   - [FieldB] (yaml:"[field_b]"): [若為指標欄位，需描述 nil 的語意。]
//   - [FieldC]: [所有欄位皆需逐一說明，無例外。]
//
// 契約 / 限制:
//   - [描述欄位之間的相依性、不允許的組合、必須遵守的外部契約。]
//   - [描述任何需要與上層 validator 配合的規則。]
//
// 備註:
//   - [列出版本演進時需同步更新的相關模組。]
//   - [描述與序列化、反序列化相關的技術限制。]
type [TypeName] struct {
    // [FieldA]: [欄位用途與限制。]
    [FieldA] [Type]

    // [FieldB]: [欄位用途與限制。]
    [FieldB] [Type]

    // [FieldC]: [欄位用途與限制。]
    [FieldC] [Type]
}
```

```
//
// 契約 / 限制:
//   - [描述呼叫順序要求、可重入特性、併發安全性保證。]
//   - [描述此介面不得依賴或洩漏的內部細節。]
//
// 備註:
//   - [描述實作端需特別注意的邏輯或必要不變條件。]

    [MethodA]([param] [Type]) ([result] [Type], error) // [描述方法的技術用途與意圖。]

}
```

# **🧪【驗收規則（Acceptance Rules）】**

以下任一項違反 → **整份輸出視為不合格，必須重寫**：

1. 未完全使用 A~H 模板任一欄位（即使無內容也不可省略）

9. 未依模板加上「功能」「參數」「回傳」「備註」等大段落
